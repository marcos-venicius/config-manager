Fresh install → ready to code

Rebuild your dev machine with one command.

config-manager installs your toolchain, links your dotfiles, sets Helix and Alacritty as defaults and applies your desktop preferences. Safe to re-run, and every step is health-checked. 

$ git clone https://github.com/marcos-venicius/config-manager.git ~/.config-manager
$ cd ~/.config-manager && go install .
$ sudo ~/go/bin/config-manager install
★ View on GitHub Read every command it runs
sudo config-manager install -ignore dotnet

Built for the day you reinstall

No more half-remembered setup notes. Your whole environment is written down as code, reviewed like code, and replayed in minutes.

✓

Health-checked & idempotent

Each step checks whether the tool is already installed and skips it if so. Run it again after a failure and it picks up where it stopped.

⛓

Dotfiles as symlinks

.bashrc, .gitconfig, tmux, Alacritty and Helix configs are linked to the repo. Edit on the machine, commit from the repo.

⤺

Nothing gets lost

Existing files are moved to .bak.<timestamp> before being replaced. Your previous setup is always one mv away.

⊘

Skip what you don't need

Steps are grouped. -ignore desktop,dotnet skips whole groups, so a server or VM gets only what makes sense for it.

🔒

Secrets stay local

Machine-specific and sensitive settings live in ~/.bashrc.local, which is sourced automatically and never committed.

🐳

Test it in Docker first

Run make and the whole pipeline runs inside a disposable Ubuntu container. Your system stays untouched.

How it works

A small Go binary that runs a readable list of shell steps. No DSL and no magic, so you can audit it in five minutes.

Declare the steps

Each step has a label, groups, commands and health checks. Adding a tool takes a few lines.

{
  label:  "Tmux",
  groups: []string{"tmux"},
  commands: []string{"apt-get install tmux -y"},
  healthCheckCommands: []string{"which tmux"},
}

Check before acting

If every health check passes, the step is skipped. Otherwise the commands run, with system steps as root and user steps as you.

Verify after acting

Health checks run again after the commands. If one fails, the pipeline stops and tells you exactly which command failed.

Heads up: these are one developer's personal configurations for Ubuntu-based systems. Fork the repository and make the pipeline yours, or run make to try it in Docker first.
